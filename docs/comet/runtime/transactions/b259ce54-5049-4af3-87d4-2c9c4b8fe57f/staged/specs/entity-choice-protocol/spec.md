# 多轮实体候选选择协议（ENTITY_CHOICE）

## 一等实体选择状态

新增 `ENTITY_CHOICE` pending 类型，不滥用 `CAPABILITY_CHOICE`。候选集保存在服务端 durable store；前端只获取授权展示字段与不透明选择句柄。

候选集至少绑定：resolution/candidate-set ID、对象类型、目标槽位、原始 mention 与必要过滤、原始候选稳定身份及展示顺序、当前 principal、conversation/frame、state version、registry/semantic 配置版本、Provider、主数据快照、创建与过期时间。

不仅依赖浏览器回传的完整候选列表，也不只靠模型记忆维护候选。

## 用户选择

同时支持按钮与受约束自然语言：

- "第二个"绑定原展示顺序，不重新检索后再取第二条。
- "苏州那家""20 毫米的"只能在当前候选真实属性中解析；仍多个则继续澄清。
- "都不是"清除当前候选，允许重述。
- 补充描述建立新候选集，旧句柄不能继续选中。
- 改业务目标/对象类型结束或显式切换旧 pending。

自然语言第一版用确定性解析（序数、否定、属性过滤）；模型解释时只能返回候选引用建议，服务端仍验证集合成员、唯一性及当前绑定。

## 确认前复核

确认时重新验证当前数据版本、实体存在与有效状态、principal/组织可见性。

快照、规则或权限变化采用保守策略：旧选择失效并要求重新解析/确认；不只凭快照不同静默替换用户选择。

覆盖重复点击、并发两个 tab、旧 state version、过期候选、跨会话/跨用户句柄与重放。继续执行遵守现有幂等/lease 协议。

## 前后端一致性

Python/TypeScript 类型、序列化、持久化校验、迁移与测试同步修改。旧会话缺少新字段时安全读取；不能迁移的旧 pending 失效，不获得新执行权威。

DSH Chat 展示真实候选属性、数据来源/时效提示及继续缩小范围的入口。pending 时不触发下游业务读取。

实体选择确认不是 WRITE 审批，不产生 ApprovalRecord；既有写审批 subject 含最终规范编码，对象改变则旧审批失效。

## 安全与审计

主数据搜索本身泄露商业信息，不因只读开放全部记录。过期阈值是受控配置，默认值声明未经生产校准；过期数据不能自动确认。

get-by-key 只证明 PG 当前快照状态，不宣称已向 SAP 实时复核。数据库文本、描述、别名为不可信业务数据，不作为指令；描述含 Prompt Injection 时不调用额外工具或泄露信息。

审计记录解析、搜索、候选确认、参数绑定、执行的关联 ID，按现有脱敏规则处理描述、名称与数据范围，不记录秘密。
