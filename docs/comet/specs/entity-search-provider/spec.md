# 实体搜索 Provider 与 Gateway 接入

## Provider/Adapter 契约

窄主数据契约：`search(request, trusted_scope)` 搜索可见候选；`get_by_key(entity_key, trusted_scope)` 验证确定编码及当前状态；数据快照/覆盖范围信息经响应携带或单独查询。

上层不依赖 PG 表结构或 PG SQL。搜索请求含：对象类型、描述/编码、语言、允许的业务过滤、分页/limit。

可信身份、系统/client、允许组织范围由服务端注入，不能由模型或请求体自行授予。

## 统一候选响应

包含：稳定实体键（来源系统、client、对象类型、规范编码）、正式名称/描述与实际可得区分属性、匹配方式及理由（exact-code、exact-label、approved-alias、substring、trigram）、数据版本/快照与来源提取/加载时间、分页/截断/覆盖范围/检索完整性信息、可选排序分数（仅属具体 Provider，不作跨库正确性概率）。

显式区分：无匹配、需要缩小范围、数据源不可用、权限不足、快照过期、覆盖不完整。异常不返回成空候选冒充"没有匹配"。

## 检索顺序

1. 编码精确查找并校验存在性；2. 正式名称/受治理别名精确匹配；3. 描述关键词、子串与结构化区分属性检索；4. pg_trgm 召回/排序作补充，不替代身份校验。

不引入 embedding。中文短词、两字词、英文型号、数字规格必须有测试；不宣称 pg_trgm 理解中文语义。

保留尺寸、小数点、型号、单位的业务差异；归一化不合并不同规格；可维护独立检索文本但原始值保留。

## SQL 与性能边界

SQL 参数化；表/列/排序仅来自白名单可信配置。字面量子串正确转义 `%`、`_` 与转义字符。有界 limit、分页、超时、连接池。

极短或无可用 trigram 的输入执行有界策略或请求更多信息，不无界全库扫描。按实际查询选 GIN/GiST/B-tree 并提供可复现 EXPLAIN；原始数据库错误不回显 SQL、连接信息或凭据。

Top-1 不等于唯一；Top-K 只有一条不等于全量唯一。响应区分 complete-result-set 与 partial/truncated，完整性只在明确授权与覆盖范围内成立。

同一实体的多语言、别名、组织 join 行先去重再决定候选数量。

## Gateway 受控 READ 接入

搜索作为注册 READ 能力经现有安全边界访问；DSH、浏览器、任意 Python 子进程不直接获得 PG 凭据。不提供任意 SQL、任意表名、任意库地址或自由查询表达式入口。

接入路线按 D2 探证选择：优先核验现有 REST_JSON Adapter 是否支持所需固定参数化请求/响应、认证、审计与网络限制（不假定兼容、不无理由新增微服务）；不足时在 Gateway 内实现窄主数据搜索 TechnicalAdapter + 新 executor 类型，并同步更新所有实际消费的 schema、模型、loader、validator、dispatcher、代码生成与测试。

## 选择策略

精确编码且当前可见、有效：可绑定，必须有验证证据。完整有效覆盖范围内精确正式名称/受治理别名唯一：第一版采取保守策略仍请求确认并展示已采用对象。

描述模糊命中即使只返回一个也请求确认。多个候选显示有用差异并请求选择。过多候选依据真实可用属性请求一个最有效补充条件。无匹配请求补充描述/型号/城市，不强迫记编码。

超时、权限不足、覆盖不完整、截断、过期分别表达，不降级成"唯一"或"没有"。
