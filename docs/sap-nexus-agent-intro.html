SECTION 01 · CONTEXT

传统 SAP Agent 的三道鸿沟，靠“换个更大的模型”跨不过去问题不在模型能力，而在业务口径、执行边界与宿主耦合

传统 SAP Agent

口径写在 prompt 与代码里
“可用库存 / 逾期 / 信用敞口”的算法随提示漂移，同问不同答。

LLM 直连 RFC / BAPI
参数、提交动作不受控，READ 可能误触发事务提交。

业务语义绑死单一宿主
换一个 Harness 就换出第二套语义，无法跨宿主一致。

SAP Nexus

口径沉淀为能力，服务端强制
端点链、时点一致性、基数归约固化，回答不随提示漂移。

Gateway 是唯一安全边界
四条红线不可由 Harness 注入，READ 不提交、WRITE 先审批。

Harness 可整体替换
只做能力选择与展示，换宿主不会换出第二套业务语义。

资料来源：项目 README02 / 12

不做又一个 Agent：四方各管一件事，能力层是唯一核心资产

SECTION 03 · PRINCIPLES
01

定义在顶

业务对象、业务口径与关系只存在于能力本体 YAML；人只在这里维护，端点不手工描述。

02

推理在编译期

Manifest 离线派生、可重放可签名；请求期不查本体，只做确定性选择与执行。

03

治理在能力内

端点链、时点一致、基数归约与审批裁决固化在服务端能力，写在代码里即视为未达成。

04

体验可替换

Harness 只做能力选择与展示；换宿主不换语义，也换不出第二套业务口径。
